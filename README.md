# store-communication-app

店舗内コミュニケーション専用アプリ（`index.html` 単体の静的アプリ + Firebase）。ホーム画面のカードから各機能を開く形式です。

## 🔄 プルリフレッシュ（引っ張って更新）

改修を重ねてアプリを継続的にアップデートしていく前提のため、画面の一番上でスマホ画面を下に引っ張ると、キャッシュを回避して最新版を再読み込みする「プルリフレッシュ」に対応しています。どの画面（ホーム・連絡ノート・チャットルームなど）からでも同じ操作で実行できます。スクロールが一番上にある状態からのみ反応するため、通常のスクロール操作や、テキスト入力・署名欄の操作の邪魔にはなりません。

## 🖼️ 画像の自動圧縮

忘れ物の写真・チャットルームや管理者チャットの画像添付・落とし物交付表ファイルは、アップロード前に自動でリサイズ・再圧縮されます（長辺1600px・JPEG品質82%を目安に、ブラウザの`<canvas>`で処理）。スマホのカメラでそのまま撮った数MB〜十数MBの写真も、実際にアップロードされるのは数百KB〜1MB程度になるため、Firebase Storageの容量やモバイル回線でのアップロード時間を節約できます。すでに小さい画像（200KB以下）やPDF・GIFはそのまま送信され、圧縮に失敗した場合も元のファイルがそのまま使われるため、アップロード自体が失敗することはありません。

## 📱 PWA対応・ホーム画面バッジ・検索・バージョン表示

- **PWA対応**: `manifest.json` を同梱し、スマホのホーム画面に追加すると専用アプリのようなアイコン・スプラッシュ表示になります（`display: standalone`）。`<head>` にはiOS向けのメタタグ（`apple-mobile-web-app-capable` 等）も含めています
- **ホーム画面バッジ**: 📝連絡ノート（本日分の引継ぎが未作成なら表示）・📌掲示板（自分がまだサインしていない「要確認」投稿の件数）・🎒忘れ物（保管中の件数）の3つのカードに、対応が必要な件数を赤バッジで表示します。該当が無い場合はバッジ自体が非表示になります
- **検索機能**: 📝連絡ノート・📌掲示板・📖マニュアルの一覧上部にリアルタイム検索欄があり、入力するとその場でタイトル・本文・投稿者などを対象に絞り込みます。0件のときは検索キーワードを含む空状態メッセージを表示します
- **バージョン表示**: ホーム画面の一番下に現在のバージョンと最終更新日時を表示します（`APP_VERSION`・`APP_BUILD_TIME` 定数）。プルリフレッシュ後にこの表示が更新されていれば最新版が読み込まれた確認になります。改修のたびにこの2つの定数を手動で更新してください
- **忘れ物タグのオーナー設定化**: 忘れ物登録時に選べる「貴重品タグ」「色」「柄」の選択肢は、🔒オーナー設定の「🚔 忘れ物・警察届出設定」内で自由に編集できます（1行に1項目）。空欄で保存すると標準のリスト（貴重品6種・色14種・柄8種）に戻ります。設定は`appSettings/general.lostItemConfig`に保存され、店舗の全端末に共有されます
- **入力・操作性の細かい改善**: すべての入力欄のフォントサイズを16px以上にし、iOS Safariでタップ時に自動ズームされる問題を防止。ボタンの最小高さを44px確保し、タップ時に軽く縮小するフィードバック（`:active`）を追加しています
- **🌐 言語切り替え（日本語 / English / नेपाली）**: 各画面右上の🌐ボタンから、外国人スタッフも使う日常画面（🏠ホーム・📝連絡ノート・📌掲示板・📖マニュアル・💬チャット・🎒忘れ物・🎓トレーニング）のボタン・ラベル・プレースホルダー・空状態メッセージを英語・ネパール語に切り替えられます。選択した言語は端末のlocalStorageに保存され、次回以降も保持されます。⚙️設定・🔒オーナー設定・🔐管理者チャット・🧾店控え書類、および投稿されたデータ本体（連絡ノートの本文やチャットメッセージなど、スタッフが実際に書いた内容）は対象外で、日本語のままです。翻訳対象を増やしたい場合は、`index.html`内の`I18N`オブジェクトにキーを追加し、該当するHTML要素に`data-i18n`（または`data-i18n-placeholder`）属性を付けてください

## 機能

- **📝 連絡ノート**: 金庫やレジ点検のように、シフトごとに用意された引継ぎ事項を点検し、次のシフトが確認するための機能です。開くとまず「最新の引継ぎ」が表示されます。自由記入欄をいきなり見せると誰も書かなくなるため、「📋 引継ぎを作成する」ボタンから、🧑‍💼「バーチャル店長」からの質問に一問一答形式で答えていくウィザードで進みます。回答タイプは4種類あります: **あり／なし**（例:「忘れ物はありませんか？」）、**件数**（0〜10と「11件以上」のボタンから選択。手入力させないことでテンポを落としません）、**写真**（例:「バックカウンターの状態を撮影してください」。撮影しないと次に進めません）、**プリセット選択**（例:「クレーム・トラブル対応はありましたか？」。「あり」のときだけ、想定されるトラブルの選択肢が複数選択で出て、詳細・写真も添えられます）。前回の引継ぎ内容は、質問の下に**小さく参考表示されるだけ**で、回答欄には引き継がれません（毎回のシフトが自分で点検し直すためです）。回答が終わると、項目ごとの定型文＋詳細を自動で組み合わせた引継ぎ書のプレビューが表示され（重要項目は先頭に【重要】付きでまとめられ、「なし」の項目は本文に出ません）、内容を確認・編集してから投稿します。投稿すると最後に「🔐 金庫アプリを開く」ボタンが出て、金庫の確認をもって引継ぎ完了という流れになります（金庫アプリのURLは🔒オーナー設定で登録。空欄なら表示されません）。投稿後は、次のシフトの担当者が「✅ 確認しました」から手書きサインを残せます（誰がいつ確認したかが記録され、本人はボタンが消えます）。引継ぎ項目自体は🔒オーナー設定から自由に追加・削除でき、回答タイプ・プリセットの選択肢・重要フラグも設定できます。一般的な項目をワンクリックで登録できるサンプル項目ボタン（10項目）も用意しています。チェックリストでカバーしきれない内容用に、「＋自由に一言追加する」から従来通りの自由記入も投稿できます
- **📌 掲示板**: お知らせを投稿し、重要なものはピン留めで先頭固定。投稿ごとに「要確認」を設定すると、スタッフは手書きサインで既読を記録します（チェックボックスだけの形骸化した既読確認を防ぐため）
- **📖 マニュアル**: カテゴリ別に業務手順書を登録し、折りたたみ表示で閲覧。1件ずつ手入力する以外に、「📥 まとめてインポート（テキスト）」から一括登録もできます（詳細は下記「📥 マニュアル・トレーニング項目のインポート」参照）
- **💬 チャットルーム**: スタッフ間でリアルタイムにメッセージをやり取り。画像・ファイルの添付にも対応（最大20MB）。画像は吹き出し内にサムネイル表示され、タップで原寸大表示、それ以外のファイルはダウンロードリンクとして表示されます
- **🎒 忘れ物管理台帳**: 拾得物を写真付きで記録し、保管中・返却済み・廃棄済みのステータスを管理。登録時にスマホ・カード・財布・鍵・身分証などの「貴重品タグ」を付けられ、リマインドの自動投稿（📝連絡ノート・💬チャットルームへ）や警察届出書の対象抽出に使われます。お客様が受け取りに来たときは「返却済みにする」から指でのサインを記録します。各記録から「🖨️ メモを印刷」でその場で落とし物メモを印刷でき、「🚔 占有者拾得物届出書を作成・印刷」からは未届出の複数の忘れ物をまとめて警察提出用の届出書（白紙にレイアウトごと再現したもの）として印刷できます。印刷すると対象は自動的に「届出済み」になります。詳細は下記「🚔 忘れ物の警察届出・印刷機能」参照
- **🎓 トレーニング管理（名称変更可）**: 研修・資格制度のステップを登録し、完了時に本人が手書きサインして進捗を記録。機能名は店舗ごとに⚙️設定から自由に変更できます（コード上に固有の制度名は含まれません。実際の名称や内容はご自身のFirebaseデータにのみ保存されます）。ステップも1件ずつ手入力する以外に、「📥 まとめてインポート（テキスト）」から一括登録できます
- **🧾 店控え書類の保管**: レシートなど毎日発生する書類をカメラで撮影、またはファイルから選択して保管。**この機能だけはFirebaseを使わず、端末（ブラウザ）内のIndexedDBにのみ保存**され、他の端末やクラウドには一切送信されません。日付ごとに一覧表示され、個別ダウンロードのほか、期間を指定してZIPでまとめてバックアップダウンロードできます
- **🔐 管理者チャット**: 管理者とスタッフ本人の1:1チャット。他の機能（店舗共通のPINコードでのログイン）とは別に、**スタッフ本人がメールアドレス＋パスワードでログインした場合のみ**、自分のスレッドが開きます。画像・ファイルの添付にも対応（最大20MB）。⚙️設定に登録したメールアドレスでログインした人は「管理者」として全スタッフのスレッド一覧（受信箱）から選んで返信できます。スタッフの初回登録はアプリ内の「初回登録」フォームから、管理者が発行した招待コードを使って行います
  - **📹 ビデオ通話（リモート店長対応）**: 管理者チャットのスレッド内から「ビデオ通話を発信」でスタッフ⇔管理者間のビデオ通話ができます。ブラウザ標準のWebRTCによるP2P通話で、発信・応答のやり取り（シグナリング）は管理者チャットと同じFirestoreを使うため追加のサーバーは不要です。**完全無料枠のプロトタイプとして、STUNサーバーのみを使いTURN中継サーバーは組み込んでいません** — 双方とも一般的なWi-Fi/モバイル回線であれば繋がりますが、企業ネットワークや一部の閉域網など厳しいNAT環境では接続できないことがあります。管理者が呼び出しを受け取るには、アプリのタブを開いてログインした状態を保っている必要があります（プッシュ通知は今回のプロトタイプには含まれていません）
- **🚨 不具合報告**: 別のFirebaseプロジェクトで動いている「不具合報告アプリ」からの報告を表示専用で確認できます。詳細は下記「🚨 不具合報告アプリとの連携」参照

上記のうち「店控え書類の保管」を除く機能は、Firestore・Firebase Storageで店舗の端末間・スタッフ間にリアルタイムに共有されます（要Firebase接続。店舗共通のPINコードでのログインが必要です）。「店控え書類の保管」は端末ローカル保存のため、端末の故障・初期化に備えて定期的なZIPバックアップを推奨します。「🔐 管理者チャット」のみ、他の機能とは別に本人のFirebaseアカウントでのログインが必要です。

## ⚙️ 設定画面の構成

設定は2階層に分かれています。⚙️設定は共通PINでログインした端末なら誰でも開けますが、🔒オーナー設定は🔐管理者チャットの管理者メールとして登録されたアカウントでログインしている場合のみ開けます（そうでない場合は、開こうとするとオーナーアカウントでのログインを求められます）。ログインすると、その端末は一時的にオーナーアカウントに切り替わり、作業が終わったら⚙️設定の「🚪 ログアウト」（または🔐管理者チャットの「ログアウト」）から共通PINに戻せます。

- **⚙️ 設定**（誰でも開く一般設定）: データ接続状況、🔥Firebaseデータベース設定、👤あなたの名前、🌐他店舗も表示するかの表示設定、🚪ログアウト
- **🔒 オーナー設定**（⚙️設定の下部ボタン→オーナーアカウントでログイン）: 🏪店舗一覧、🚔忘れ物・警察届出設定（店名・住所・電話・占有者コード・権利区分デフォルト・交付表ファイル・貴重品タグ/色/柄の選択肢）、📋引継ぎ項目（連絡ノートの一問一答の質問・定型文）、🔑店舗共通PINコードの変更、🎓トレーニング機能の名称、🔐管理者チャット設定（管理者メール・招待コード）、🚨不具合報告アプリ連携設定、🔐金庫アプリ連携設定（URL・接続情報・店舗名の対応付け）、🏦金庫の現在の状況を確認。引継ぎ項目（`handoverItems`）の追加・削除はFirestoreルールでもオーナー（管理者メール）のみに制限されています（他の項目は今のところアプリ画面上の制限のみです）

**🔥Firebaseデータベース設定は、意図的に⚙️設定（ログイン不要）側に置いています。** Firebase接続はログインより前に必要なブートストラップ手順のため、ここをオーナー設定の中に置くと、接続情報が未設定の端末では「ログインするには接続が必要、接続情報を入力するにはログインが必要」という詰みが発生します。Config自体は公開前提の情報で、実際の保護はFirestore/Storageのルール側で行っています。

⚙️設定の「🚪 ログアウト」は、サインイン中のみ表示されます。共通PINでログインしている間、ログアウトの導線が🔐管理者チャット内（個人アカウントでのログイン中しか表示されない）にしかないと、店舗別PINの切り替えがブラウザのデータ削除以外にできなくなるため用意しています。

## 🔐 セキュリティ仕様

このアプリのログイン・アクセス制御の全体像をまとめます。

### ログインは2種類

- **共通PIN（店舗全体で共有）**: Firebase Authenticationに `staff@<projectId>.local`（単一店舗）または `staff01@<projectId>.local`〜`staff05@<projectId>.local`（店舗ごとに別PINにする場合）というアカウントを作り、PINコード＝そのアカウントのパスワードとして扱います。📝連絡ノート・📌掲示板・📖マニュアル・💬チャット・🎒忘れ物・🎓トレーニングなど、通常機能のほぼ全てがこのログインでアクセスします。店舗別PINでログインした場合、対応する店舗（🏪店舗一覧の何行目かで対応）が自動的に選択されます（詳細は「複数店舗運用」参照）。匿名認証は使っていません。ログインに成功したメールアドレスは端末に記憶され、次回以降はそれを最初に試すため、通常のログインはFirebase Authへの試行が1回で済みます（候補を毎回複数試すと、Firebase側の連続失敗検知でしばらく全ログインがロックされることがあるため）。
- **個人アカウント（🔐管理者チャット・🔒オーナー設定用）**: スタッフ本人のメールアドレス＋パスワードでログインします。初回はアプリ内の「初回登録」フォームから、オーナーが発行した招待コードを使って自己登録します。このアカウントのメールアドレスが⚙️→🔒オーナー設定の「管理者メールアドレス」一覧に含まれていると、「管理者」として扱われます。ログインすると、その端末は一時的にこの個人アカウントに切り替わります（共通PINのセッションとは同時に併存できません。Firebase Authは1端末につき1セッションのため）。ログアウトすると自動的に共通PINのセッションに戻ります。

### 画面ごとのアクセス制限

| 画面 | 必要なログイン |
|---|---|
| 📝連絡ノート・📌掲示板・📖マニュアル・💬チャット・🎒忘れ物・🎓トレーニング、⚙️設定 | 共通PIN（または管理者個人アカウント）でログイン済みであればOK |
| 🔒オーナー設定 | 管理者メール一覧に登録された個人アカウントでログイン必須 |
| 🔐管理者チャットの受信箱（全スタッフのスレッド一覧） | 管理者メール一覧に登録された個人アカウントでログイン必須 |
| 🔐管理者チャットの自分のスレッド | 本人の個人アカウントでログイン必須（他人のスレッドは見えません） |

### Firestore/Storageのルール（サーバー側の強制）

- ほとんどのコレクション（`notebookEntries`・`bulletinPosts`・`chatMessages`等）は「ログイン済みなら誰でも読み書き可」という単純なルールです。共通PINでログインしていればOK、というシンプル設計です
- `handoverItems`（連絡ノートの引継ぎ質問項目）だけは、読み取りは全端末共通ですが、**書き込みは管理者メールのアカウントのみ**にFirestoreルールで制限されています（devtoolsからの直接アクセスでも回避できません）
- `dmChannels`（管理者チャットのDM）・ビデオ通話のシグナリングは、**本人のuid、または管理者メールのアカウントのみ**アクセス可能です。匿名ログインでは一切アクセスできません
- 上記以外（🔒オーナー設定の大半の項目、店舗一覧、招待コードなど）は、UI（アプリ画面）上ではオーナー専用ボタンの奥に隠れていますが、Firestoreルール自体は「ログイン済みなら誰でも書き込み可」のままです。これは、自動リマインド機能などが共通PINでログインしたどの端末からでも書き込む必要があるためで、技術に詳しいスタッフがdevtoolsを使えば理論上は回避できてしまいます
- Firebase Storage（画像・添付ファイル）は「ログイン済みなら読み書き可」のみの単純なルールです。**`getDownloadURL()`が返すURLはアクセストークン付きの直リンクのため、そのURL自体が漏えいすると認証なしで閲覧できてしまいます**（忘れ物の写真・管理者チャットの添付ファイル共通の制約）。対策として、URLはFirestore側のドキュメント（アクセス制御あり）にのみ保存し、アプリ外に表示・共有はしていません

### 公開・配布について

このリポジトリの `index.html` はGitHub Pagesで誰でも閲覧できる状態で公開されていますが、これは「コードを配布している」だけで、**データは共有されません**。使いたい人が⚙️設定から自分自身のFirebase Configを貼り付けると、その人自身のFirebaseプロジェクトに接続され、そちらのデータとは完全に分離されます。ConfigはブラウザのlocalStorageに保存されるだけです。

### 既知の制約

- ブラウザのキャッシュ・サイトデータを消去すると、保存していたFirebase Configも一緒に消えます（再設定が必要になります）。復旧方法は後述の「🆘 ログインできないときの復旧手順」を参照してください
- 共通PINは「端末の共有利用」を前提にした設計のため、個人の行動追跡はできません（投稿者名は自己申告の「名前」欄によります）
- 上記の通り、`appSettings`など一部のコレクションはFirestoreルール上は誰でも書き込み可能なため、アプリ画面上の制限を過信せず、共通PINの取り扱いには注意してください

## 🆘 ログインできないときの復旧手順

**最初に、エラーメッセージを必ず読んでください。** 症状が同じ「ログインできない」でも原因は全く別で、文面で判別できます。

| 画面に出るメッセージ | 原因 | 対処 |
|---|---|---|
| `No Firebase App '[DEFAULT]' has been created` | この端末にFirebase Configが入っていない（キャッシュ削除・新しい端末・別ブラウザ） | ⚙️設定→🔥Firebaseデータベース設定にConfigを貼り付け（**ログイン不要**） |
| `PINコードが違います` | PINがそのアカウントのパスワードと一致しない、または該当アカウントが存在しない | 下記「PINが分からなくなった場合」へ |
| `ログイン試行が続いたため一時的に制限されています` | Firebase側の連続失敗検知（`auth/too-many-requests`） | しばらく待つ。強制解除する手段はありません |
| `auth/operation-not-allowed` を含む | Firebase Console→Authentication→ログイン方法で「メール/パスワード」が無効 | 有効にする |

### ⚠️ やってはいけないこと

**「ブラウザのサイトデータを消す」を復旧手段として使わないでください。** Firebase Configも一緒に消えるため、上表の1行目の状態を自分で作り出すことになり、状況が悪化します。アカウントを切り替えたいだけなら、⚙️設定の「🚪 ログアウト」を使ってください。

**Firestore/Storageのセキュリティルールは、ログインの成否とは無関係です。** ルールはログイン「後」のデータアクセスを制御するもので、認証そのものはAuthenticationが担当します。ログインできない問題の調査でルールを見ても原因は見つかりません（ルールが原因なら「ログインは通るがデータが出ない」という症状になります）。

### アカウントの命名規則（完全一致が必要）

Firebase Console→Authentication→ユーザーに、以下の綴りで登録されている必要があります。1文字でも違うとアプリ側の判定に一致せず、正しいPINでも「PINコードが違います」になります。

- 共通PIN（単一店舗）: `staff@<projectId>.local`
- 店舗別PIN: `staff01@<projectId>.local` 〜 `staff05@<projectId>.local`（**数字は必ず2桁**。`staff1@` は認識されません）
- パスワード（PIN）は**6文字以上**（Firebaseの必須要件）
- 店舗別PINを使う場合、各アカウントのPINは**それぞれ別のものにしてください**。ログイン処理は `staff@` → `staff01@` → `staff02@` … の順に試すため、同じPINだと先にヒットしたアカウントでログインしてしまい、店舗の自動選択が意図通りに効きません

### PINが分からなくなった場合

1. **まずオーナーでアプリに入る** — PIN画面の「🔑 オーナー（管理者）としてログイン」から、管理者個人アカウントのメールアドレス＋パスワードでログインします。これでPINに依存せずアプリに入れます
2. **PINを再設定する** — Firebase Console→Authentication→ユーザーで該当の `staff...@...local` アカウントを削除し、「ユーザーを追加」で**同じメールアドレス**＋新しいPIN（6文字以上）で作り直します

`.local` のアドレスはメールが届かないため、パスワード再設定メールは使えません。削除して作り直すのが唯一の方法です。なお、アプリ内の🔒オーナー設定→🔑店舗共通PINコードの変更は、**共通PINでログイン中**かつ**現在のPINを知っている**場合のみ使えます（既存PINの変更用であり、忘れた場合の復旧には使えません）。

### オーナーのパスワードが分からなくなった場合

管理者個人アカウントは実在のメールアドレスなので、Firebase Console→Authentication→ユーザー→⋮メニューの「パスワードの再設定メールを送信」が使えます。**削除せずに再設定してください。** 削除して作り直すとUIDが変わり、🔐管理者チャットのDM履歴（`staffProfiles/{uid}`・`dmChannels/{uid}`）が孤立します。

### アカウントを削除してもデータは消えません

連絡ノート・掲示板・マニュアル・忘れ物・トレーニング・店控え・店舗一覧・管理者メール一覧は、店舗名やメールアドレスをキーにFirestoreへ保存されており、**Authenticationのアカウント削除では消えません**。UIDに紐づくのは🔐管理者チャットのDM履歴のみです。管理者メール一覧はメールアドレスで保持されるため、同じアドレスで作り直せば管理者権限もそのまま復帰します。

## 複数店舗運用

1つのFirebaseプロジェクトを複数店舗で共有し、店舗ごとにデータを緩やかに区分けできます（アクセス制限はかけず、「基本は自店舗、必要なら他店舗も見える」という前提の設計です）。

- **店舗一覧**: オーナー（管理者）が ⚙️→「🔒 オーナー設定」→「🏪 店舗一覧」で店舗名を登録します（1行に1店舗）
- **現在の店舗**: 各端末が「今どの店舗にいるか」を表す設定です。ホーム画面上部の「📍◯◯店 ▾」ボタンからいつでも切り替えられ、店舗が2つ以上登録されている状態でアプリを開くたびに選択モーダルが表示されます（店舗が1つしかない場合は自動的にそれが選ばれ、モーダルは出ません）。📝連絡ノート・🎒忘れ物管理台帳・💬チャットルーム・🧾店控え書類の保管は、この店舗に投稿され、通常はこの店舗の分だけ表示されます
- **🌐 他店舗の投稿・記録も表示する**: ⚙️設定の「表示設定」にあるチェックボックスです。入れると上記4機能で全店舗分をまとめて表示できます（閲覧のみの切り替えで、投稿先は常に「現在の店舗」のままです）
- **📌 掲示板・🎓 トレーニング管理**: 常に全店舗共通の1画面です。投稿・ステップごとに対象店舗タグを複数選択でき、未選択は「全店共通」として全店舗に表示されます。画面上部の「店舗で絞り込み」で特定店舗向け（＋全店共通）だけに絞り込めます
- **📖 マニュアル**: 店舗の区別はなく、常に全店舗共通です

店舗名はFirestoreの `appSettings/general.stores` に保存されます。セキュリティルール上はどの店舗のデータも全スタッフが閲覧・投稿できる想定のため、この機能追加によるFirestore/Storageルールの変更はありません（店舗名は単なる分類用フィールドとして各ドキュメントに追加されます）。

## 📥 マニュアル・トレーニング項目のインポート

紙のマニュアルや研修資料を1件ずつ手入力するのは大変なので、📖マニュアルと🎓トレーニング管理には「📥 まとめてインポート（テキスト）」という一括登録機能があります。生成AI（Claude等）に紙の資料の写真やPDFを読み取らせて専用のテキスト形式を作らせ、それをアプリに貼り付けるだけで反映できます（JSONではなく、行ごとに「ラベル: 内容」を書くだけの簡易テキスト形式です。AIが多少崩して出力しても壊れにくく、貼り付けた内容がそのまま画面に読みやすく表示されるようにしています）。

**使い方**

1. 📖マニュアル または 🎓トレーニング管理の画面を開き、「📥 まとめてインポート（テキスト）」を開く
2. 中にある「Claudeへの指示文」を「📋 コピー」ボタンでコピーする
3. Claude（[claude.ai](https://claude.ai) など）に新しいチャットを開き、コピーした指示文と一緒に、紙のマニュアル・資料を撮影した写真やPDFを添付して送信する
4. Claudeが返してきたテキストをコピーし、アプリの「テキストを直接貼り付け」欄に貼り付けるか、`.txt`/`.md` ファイルとして保存してから「テキストファイルを選択」でアップロードする
5. 「📝 内容を確認する」を押すと、認識された項目が一覧プレビューとして表示される。項目ごとにチェックボックスで登録するかどうかを選べ、形式が崩れていて読み取れなかった項目はエラーとして個別に表示される（何件目のどの行が原因かが分かります）
6. 内容を確認し、「✏️ 修正する」で貼り付けたテキストに戻って直す、または「📥 登録する」でチェックの入った項目だけを登録する

**テキスト形式**

- 📖マニュアル: 1項目につき `カテゴリ: ...` `タイトル: ...` `本文:`（次の行以降が本文）を書き、項目の間を `---` だけの行で区切ります。`タイトル:` の行が無い項目はプレビュー時にエラー扱いになります。`カテゴリ:` を省略すると「その他」になります
- 🎓トレーニング管理: 1項目につき `タイトル: ...` と、対象店舗を絞る場合だけ `対象店舗: 店舗名, 店舗名` （読点 `、` またはカンマ `,` 区切り）を書き、`---` で区切ります。`対象店舗:` を省略すると全店共通になります。店舗名は🔒オーナー設定の「🏪店舗一覧」に登録済みの名前と完全一致させてください（一致しない名前はプレビュー画面でその項目に警告付きで表示されますが、そのまま登録することも可能です）

登録は選択した項目についてFirestoreへの通常の追加（1件ずつの `add()`）として行われるため、既存データは上書きされず追記されます。重複して取り込んでしまった場合は、各項目の「削除」ボタンから個別に削除してください。

## 🚔 忘れ物の警察届出・印刷機能

忘れ物管理をより実務に近い形にするため、登録項目の入力しやすさ・リマインド表示・2種類の印刷機能を用意しています。

**📝 登録項目**（拾得物を登録する画面）

- **品名・発見場所**: 一度使った値がその場でリスト化され、次回からは入力欄に候補として表示されます（ブラウザ標準の入力候補機能を利用）。リストにない新しい品名・場所はそのまま自由に入力でき、登録すると自動的に次回からの候補に追加されます（Firestoreの`appSettings/general`に`lostItemNames`・`lostLocationNames`として保存され、全店舗・全端末で共有されます）
- **色・柄**: 色（黒・白・グレー・赤・オレンジ・黄・緑・青・紫・ピンク・茶・金・銀・その他）と柄（無地・ボーダー・チェック・ドット・花柄・迷彩・ロゴ／ブランド柄・その他）をそれぞれ複数選択できます。それ以外の特徴は自由入力欄（特徴の補足）に書けます
- **発見日時**: 発見日は日付入力（初期値は今日）、発見時刻は15分刻みのリストから選択します。入力担当者がその場でスマホの時計を見ながら記入するときのズレを防ぐため、あえて自由入力の時刻欄ではなく15分単位の選択式にしています

**リマインド**（📝連絡ノート・💬チャットルームに自動投稿されます。忘れ物管理台帳は毎日開くとは限らないため、スタッフが日常的に見ている画面に届く形にしています。投稿者名は「🔔 自動リマインド」と表示されます）

- 📅 **月末リマインド**: 月末3日間、店舗ごとに1回だけ「今月分の忘れ物は◯件です」という内容を投稿します
- 🗑️ **保管期限リマインド**: 発見日から3ヶ月を超えて「保管中」のままの忘れ物が新たに出るたびに、その忘れ物ごとに1回だけ投稿します
- 🚔 **貴重品の警察届出リマインド**: 貴重品タグを付けて登録した時点で1回、届出（占有者拾得物届出書の印刷）がまだ済んでいないまま発見日から7日を超えた時点でもう1回（🚨期限超過として）、その忘れ物ごとに投稿します

これらはリアルタイムのプッシュ通知ではなく、誰かの端末でアプリが忘れ物データを受信した瞬間に判定・投稿される仕組みです（サーバーを持たない構成のため）。同じ条件を複数の端末がほぼ同時に検知した場合、ごく稀に同じ内容が重複して投稿されることがあります。一度投稿された条件は忘れ物の記録側に印（`disposalReminderPostedAt`等のタイムスタンプ）が付き、以後は再投稿されません。

**🖨️ 落とし物メモの印刷**（各忘れ物の「🖨️ メモを印刷」ボタン）

品名・特徴・発見日・発見場所・貴重品タグ・状態（保管中/返却済み/廃棄済み）・写真・（返却済みの場合は）引き渡し先とお客様のサインをレイアウトし、ブラウザの印刷機能でその場で印刷できます。店名・住所・電話番号は🔒オーナー設定で登録したものがヘッダーに入ります。

**🚔 占有者拾得物届出書の印刷**（「🚔 占有者拾得物届出書を作成・印刷」ボタン）

保管中かつ未届出の忘れ物一覧から、届け出る項目にチェックを入れ、物品コード・点数・権利区分（1.有権/2.失権）を項目ごとに指定し、届出日・受理番号を入力して印刷します。印刷される書式は警察に提出する「占有者拾得物届出書」のレイアウトをアプリ内で再現したもので、**実物の専用用紙は使わず、白紙にレイアウトごと印刷**します（現金の内訳欄など、物品の届出には使わない欄は省略しています）。印刷すると、選択した項目は自動的に「届出済み」（✅バッジ表示）になり、リマインド対象から外れます。店名・住所・電話・占有者コード・権利区分のデフォルト値は🔒オーナー設定の「🚔 忘れ物・警察届出設定」から登録します。

**📄 落とし物交付表ファイルの保管**（🔒オーナー設定の「🚔 忘れ物・警察届出設定」内）

お店で使っている独自の交付表・案内文などのファイル（画像・PDF）をFirebase Storageにアップロードして保管しておける機能です。印刷される書類そのものには使われず、スタッフがいつでも参照・ダウンロードできる資料置き場としての位置づけです。

**お客様の受け取りサイン**（各忘れ物の「返却済みにする」ボタン）

引き渡し先の氏名を入力すると、続けて手書きサインのモーダルが開きます。お客様に画面上へ指でサインしていただくと、そのサイン画像が記録に保存され、一覧・印刷メモの両方に反映されます。

## 🚨 不具合報告アプリとの連携

並行して運用している「不具合報告アプリ」（別のFirebaseプロジェクト `store-trouble-report`）からの報告を、ホーム画面の「🚨不具合報告」から**表示専用**で確認できます。

- 別プロジェクトのFirestoreを、閲覧専用アカウントで直接購読しています（Firebase JS SDKの複数アプリ初期化機能`firebase.initializeApp(config, 'アプリ名')`を使用）。こちらのアプリからの書き込みは一切できません
- 表示専用のため、ステータス（未対応／対応中／完了）の変更は不具合報告アプリ側で行ってください。変更はリアルタイムでこちらの表示にも反映されます
- 写真は容量削減のため報告本体とは別のコレクションに分かれており、「📷 写真を見る」を押したときだけ読み込みます（一覧を開いただけでは写真の転送は発生しません）
- 店舗の突き合わせは、報告に入っている`store_name`の文字列と、こちらの🏪店舗一覧の登録名を**完全一致**で行います。表記が一致しない報告は「店舗不明」「店舗一覧に一致なし」として表示されます（消えることはありません）。両アプリで店舗名の表記を揃えてください
- **接続情報（Firebase Config・閲覧専用アカウントのメール・パスワード）はコードに埋め込まず、⚙️→🔒オーナー設定の「🚨 不具合報告アプリ連携設定」からJSON形式で貼り付けて設定します。** `appSettings/general.troubleReportConfig`としてこちらのFirestoreに保存され、店舗の全端末で共有されます。この設定は他の設定項目（招待コード等）と同じ扱いで、Firestoreのルール上「ログイン済みなら読み書き可」です。書き込み権限のないアカウントのため改ざんの心配はありませんが、共通PINでログインした端末からは閲覧できる情報である点は認識しておいてください

## 🔐 金庫アプリとの連携

別のFirebaseプロジェクトで運用している「金庫アプリ」（金庫とレジの現金点検）の結果を、このアプリから**読み取り専用**で参照します。不具合報告アプリと同じく、複数アプリ初期化（`firebase.initializeApp(config, 'kinkoApp')`）で閲覧専用アカウントを使って直接読んでいます。書き込みは一切しません。

これまでLINEやメールで共有していた点検結果を、引継ぎ書と同じ場所に置いて、いつでも見返せる・印刷できるようにすることが狙いです。

**引継ぎ書への取り込み**

- 連絡ノートの各引継ぎに「🔐 金庫の結果を取り込む」ボタンが出ます。押すと、その引継ぎの店舗の**最新の点検記録**が引継ぎ書の一部として保存されます（`notebookEntries` の `kinkoRecord`）
- 取り込んだ内容は「最新の引継ぎ」カードにも表示され、**印刷にもそのまま入ります**。金庫アプリのA4レポートと同じ項目（点検日時・金庫の実査合計／設定金額／過不足・レジごとの担当者と現金過不足・無料券・割引券・備考）を並べています
- 過不足は、金庫アプリ側の「累計」と「今回分」が違うときだけ `-300（今回分 -100）` のように併記します。担当者の責任範囲は今回分のほうなので、累計だけを見て誤解しないためです
- 一度取り込むと値は固定されます（あとから金庫アプリ側が修正されても遡って書き換わりません）。その時点の引継ぎ記録として残す扱いです

**店舗名の対応付け**

両アプリで店舗名の付け方が違う場合（例: こちら「清川二丁目」／金庫アプリ「福岡清川二丁目店」）、🔒オーナー設定の「金庫アプリの店舗の対応付け」に `このアプリの店舗名 = 金庫アプリの店舗名` の形で1行ずつ登録します。名前が同じ店舗は書く必要はありません。対応付けが見つからない場合は、金庫アプリ側に登録されている店舗名の一覧を添えたエラーを出します（黙って失敗しません）。

**🏦 事務所金庫（バックルーム）の確認**

店舗の引継ぎには紐づかない事務所金庫などは、🔒オーナー設定の「🏦 金庫の現在の状況を確認」から、金庫アプリに登録されている**すべての金庫**の最新の点検結果をその場で読めます。責任者が現在の状態を確認するためのもので、**このアプリにはどこにも保存しません**（古い値が残らず、スタッフの画面にも出ません）。

**接続情報**

不具合報告アプリと同じ方針で、Firebase Config・閲覧専用アカウントのメール／パスワードは**コードに埋め込まず**、⚙️→🔒オーナー設定の「金庫アプリ連携設定 (JSON)」からJSONを貼り付けて設定します。`appSettings/general.kinkoConfig` としてこちらのFirestoreに保存され、店舗の全端末で共有されます。書き込み権限のないアカウントのため改ざんの心配はありませんが、共通PINでログインした端末からは閲覧できる情報である点は認識しておいてください。

## セットアップ

### 1. Firebaseプロジェクトの準備

1. [Firebaseコンソール](https://console.firebase.google.com/)で新規プロジェクトを作成
2. 「Firestore Database」を作成（本番モードでOK）
3. 「Storage」を作成（忘れ物の写真・管理者チャットの添付ファイルのアップロードに使用）
4. 「Authentication」→「Sign-in method」で「メール / パスワード」プロバイダを有効化
   - 連絡ノート・掲示板・マニュアル・チャット・忘れ物・トレーニング管理は、店舗共通の1つのPINコードでログインします（手順8で登録する共通アカウントを、内部的にはこのメール/パスワード認証で扱います）
   - 🔐管理者チャットのみ、スタッフ本人のメールアドレス＋パスワードでの個別ログイン・自己登録を使います
5. Firestoreの「ルール」を以下のように設定

   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       function isSignedIn() { return request.auth != null; }
       function isAnonymous() { return request.auth.token.firebase.sign_in_provider == 'anonymous'; }
       function isAdminEmail() {
         return isSignedIn() && !isAnonymous() &&
           exists(/databases/$(database)/documents/appSettings/general) &&
           (request.auth.token.email.lower() in
             get(/databases/$(database)/documents/appSettings/general).data.adminEmails);
       }

       // 連絡ノート・掲示板・マニュアル・チャット・忘れ物・トレーニング管理・アプリ設定
       // (店舗共通PINでログインした端末も含め、全ログイン済み端末で共有)
       match /notebookEntries/{id} { allow read, write: if isSignedIn(); }
       // 引継ぎ項目の追加・削除はオーナー(管理者メール)のみ。読み取りは全端末で共有。
       match /handoverItems/{id} {
         allow read: if isSignedIn();
         allow write: if isAdminEmail();
       }
       match /handoverConfirmations/{id} { allow read, write: if isSignedIn(); }
       match /bulletinPosts/{id} { allow read, write: if isSignedIn(); }
       match /bulletinAcks/{id} { allow read, write: if isSignedIn(); }
       match /manuals/{id} { allow read, write: if isSignedIn(); }
       match /chatMessages/{id} { allow read, write: if isSignedIn(); }
       match /lostItems/{id} { allow read, write: if isSignedIn(); }
       match /trainingSteps/{id} { allow read, write: if isSignedIn(); }
       match /trainingCompletions/{id} { allow read, write: if isSignedIn(); }
       match /appSettings/{id} { allow read, write: if isSignedIn(); }

       // 管理者チャット用: 本人のプロフィール (自分のuidの行だけ本人が作成・更新可)
       match /staffProfiles/{uid} {
         allow read: if isSignedIn();
         allow create, update: if isSignedIn() && !isAnonymous() && request.auth.uid == uid;
       }

       // 管理者チャット用: 本人のスレッドのみ本人が、全スレッドは管理者メールのみ閲覧・返信可
       match /dmChannels/{staffUid} {
         allow read, write: if isSignedIn() && !isAnonymous() &&
           (request.auth.uid == staffUid || isAdminEmail());

         match /messages/{msgId} {
           allow read: if isSignedIn() && !isAnonymous() &&
             (request.auth.uid == staffUid || isAdminEmail());
           allow create: if isSignedIn() && !isAnonymous() &&
             (request.auth.uid == staffUid || isAdminEmail()) &&
             request.resource.data.senderUid == request.auth.uid;
           allow update, delete: if false;
         }

         // ビデオ通話のシグナリング (発信・応答・ICE候補のやり取り)
         match /calls/{callId} {
           allow read, create, update: if isSignedIn() && !isAnonymous() &&
             (request.auth.uid == staffUid || isAdminEmail());
           allow delete: if false;

           match /callerCandidates/{cid} {
             allow read, create: if isSignedIn() && !isAnonymous() &&
               (request.auth.uid == staffUid || isAdminEmail());
             allow update, delete: if false;
           }
           match /calleeCandidates/{cid} {
             allow read, create: if isSignedIn() && !isAnonymous() &&
               (request.auth.uid == staffUid || isAdminEmail());
             allow update, delete: if false;
           }
         }
       }
     }
   }
   ```

   `isAdminEmail()` は ⚙️設定の「管理者チャット設定」に登録したメールアドレス一覧（`appSettings/general.adminEmails`）と、ログイン中のメールアドレスを比較しています。管理者を追加・削除したい場合はアプリ側の設定画面から変更でき、Firebaseコンソールでルールを書き換える必要はありません。

   > 管理者は自分宛ての着信を全スタッフ分まとめて検知するために `calls` コレクショングループに対してクエリしますが、上記ルールは各ドキュメントの実際のパス（`dmChannels/{staffUid}/calls/{callId}`）に対して個別に評価されるため、コレクショングループクエリでも同じ権限がそのまま適用されます。Firestoreの単一フィールドインデックスは自動作成されるため、このクエリのために手動でインデックスを作成する必要はありません。

   > 同じ内容はリポジトリの [`firestore.rules`](./firestore.rules) にも入っています。手動でコンソールに貼り付ける代わりに、下記「Firestore/Storageルールの自動デプロイ」の設定をしておけば、このファイルを編集してpushするだけで自動反映されます。

6. Storageの「ルール」を以下のように設定（店舗共通PIN・個人メール認証を問わず、ログイン済み端末のみ読み書き許可）

   ```
   rules_version = '2';
   service firebase.storage {
     match /b/{bucket}/o {
       match /{allPaths=**} {
         allow read, write: if request.auth != null;
       }
     }
   }
   ```

   > **注記**: `getDownloadURL()` が返すURLはアクセストークン付きの直リンクのため、そのURL自体が漏えいすると認証なしで閲覧できてしまいます（忘れ物の写真・管理者チャットの添付ファイル共通の制約です）。URLはFirestore側のドキュメント（アクセス制御あり）にのみ保存され、アプリ外に表示・共有はしていません。

   > 同じ内容はリポジトリの [`storage.rules`](./storage.rules) にも入っています。

7. 「プロジェクトの設定」→「マイアプリ」でウェブアプリを追加し、表示される `firebaseConfig` オブジェクトをコピー（この中の `projectId` の値を、次の手順8のメールアドレスに使います）
8. Authentication → Users → 「ユーザーを追加」で、以下の内容で店舗共通アカウントを登録する（📝連絡ノートなど通常機能のPINログイン用。🔐管理者チャットの個人アカウントとは別です）
   - 単一店舗運用の場合はメールアドレス: `staff@<手順7のprojectId>.local`（例: `projectId` が `my-store-1234` なら `staff@my-store-1234.local`）を1件だけ登録
   - **複数店舗で店舗ごとに別のPINを使いたい場合**は、`staff01@<projectId>.local`・`staff02@<projectId>.local`…と店舗ごとに1件ずつ登録する（番号は2桁、`staff01`〜`staff05`まで対応）。それぞれ別のパスワード（PIN）を設定してください。**同じPINを複数の店舗で使うと、番号の若い方の店舗として自動認識されてしまう**ため、必ず店舗ごとに異なるPINにしてください
   - パスワード: この店舗で運用したいPINコード（Firebaseの制約で **6文字以上** が必要）

   > 最初の1回だけこの手順でFirebase Consoleから作成すれば、以降のPINコード変更は🔒オーナー設定の「🔑 店舗共通PINコードの変更」からアプリ内で行えます（Consoleを開き直す必要はありません）。
   >
   > 店舗別PIN（`staff01`〜）でログインすると、🔒オーナー設定の「🏪 店舗一覧」の**何行目に登録されているか**（1行目→01、2行目→02…）に対応する店舗が自動的に選択されます。店舗一覧の行の順番を変えると対応関係も変わるので注意してください。

### 2. アプリ側でFirebaseに接続

`index.html` をブラウザで開き、右上の ⚙️ から「🔥 Firebaseデータベース設定」を開いて、手順1でコピーした `firebaseConfig` をJSONとして貼り付けて保存してください。保存すると画面が再読み込みされ、PINコードの入力画面が表示されるので、手順8で決めたPINコードを入力してログインします。

同じ ⚙️ メニューから、投稿者名・サインの記名に使う「あなたの名前」も設定してください（共有端末の場合は、使う人が変わるたびに更新してください）。

トレーニング機能の名称（店舗独自の制度名など）も ⚙️ メニューから変更できます。この設定はFirebase上に保存され、同じ店舗の全端末に共有されます。

これで店舗のタブレット（PINコードでログイン済み・共有利用）から、連絡ノート・掲示板・マニュアル・チャット・忘れ物・トレーニング管理がスタッフ間でリアルタイムに共有されるようになります。ログインは端末に保存されるため、一度PINコードを入力すればその端末では再入力の必要はありません。

### 3. 🔐管理者チャットの設定（本人認証）

1. ⚙️メニューの「管理者チャット設定」で、管理者にしたい人のメールアドレスを1行ずつ登録し、招待コード（第三者に推測されにくいもの）を設定します
2. スタッフには招待コードを口頭・メモなどで伝えてください
3. 各スタッフ（管理者になる人も含む）は、ホーム画面の「🔐管理者チャット」→「初回登録」から、名前・メールアドレス・パスワード・招待コードを入力して自分のアカウントを作成します
4. 登録したメールアドレスが手順1の管理者一覧に含まれていれば、そのアカウントでログインしたときだけ全スタッフのスレッド一覧（受信箱）が表示されます。含まれていなければ、自分自身と管理者だけが見られる個人スレッドが表示されます
5. ログアウトすると、端末は自動的に店舗共通PINのアカウントに戻り、他の機能は共有端末として引き続き使えます

管理者を増やしたい・入れ替えたい場合も、Firebaseコンソールを操作する必要はなく、⚙️設定の管理者メールアドレス一覧を編集するだけで反映されます。

### 4. 📹ビデオ通話（リモート店長対応）を使う

1. 管理者チャットのスレッドを開いた状態（スタッフなら自分のスレッド、管理者ならスタッフを選んで開いたスレッド）で「📹 ビデオ通話を発信」を押すと、相手が同じ機能を開いていなくても着信が届きます（管理者はどのスタッフから発信されても着信バナーが表示されます）
2. 相手が「応答する」を押すとカメラ・マイクへのアクセス許可が求められ、許可すると通話が始まります
3. 通話中は 🎤（ミュート）・📷（カメラのON/OFF）・📞（終了）が操作できます
4. ブラウザには HTTPS（または `localhost`）でアクセスしている必要があります（カメラ・マイクの利用に必須のブラウザ制約です）。GitHub PagesやFirebase Hostingなど、通常の静的ホスティングは標準でHTTPSなので問題ありません
5. TURN中継サーバーを使わない構成のため、双方が同じような一般的なネットワーク（自宅Wi-Fi・モバイル回線など）にいれば繋がりますが、厳しいファイアウォール環境では接続できないことがあります。安定運用したくなった場合は、有料のTURNサービス（Twilioなど）か自前のcoturnサーバーの追加をご検討ください

## ホスティング（GitHub Pagesへの自動デプロイ）

`index.html` は単体の静的ファイルなので、Firebase Hosting・GitHub Pages・Netlifyなど任意の静的ホスティングにそのまま配置できます。

このリポジトリには `.github/workflows/deploy-pages.yml` を同梱しており、`main` ブランチにpushするたびに自動でGitHub Pagesへデプロイされます（ビルド不要、リポジトリのファイルをそのまま公開）。有効にするには、リポジトリの管理者権限が必要な設定を1回だけ行ってください（これはGitHub Appの権限では変更できないため、リポジトリオーナーの方の操作が必要です）。

1. GitHubの当リポジトリで **Settings → Pages** を開く
2. **Build and deployment → Source** を `Deploy from a branch` から **`GitHub Actions`** に変更する
3. `main` ブランチにpush（または `Actions` タブから `Deploy to GitHub Pages` ワークフローを手動実行）すると数十秒でデプロイされ、`https://<ユーザー名>.github.io/store-communication-app/` で公開されます

以降は `main` にpushするだけで自動的に最新版が反映されます。デプロイ状況は `Actions` タブから確認できます。

## Firestore/Storageルールの自動デプロイ（任意）

`firestore.rules`・`storage.rules` を編集してpushするだけで、Firebaseコンソールを開かずにルールを反映できるようにする設定です。必須ではありません（手動でコンソールに貼り付ける運用のままでも問題ありません）が、今後ルールを改修する機会が多い場合はおすすめです。

### 1. サービスアカウントの秘密鍵を発行（Firebaseコンソール）

1. 対象のFirebaseプロジェクトで「プロジェクトの設定」→「サービスアカウント」タブを開く
2. 「新しい秘密鍵の生成」をクリックし、JSONファイルをダウンロードする
3. ⚠️ **このJSONファイルの中身（秘密鍵）は誰にも共有しないでください**（Claudeとのチャットにも貼らないでください）。手順4で使うのはファイルの中身そのものです

### 2. Google Cloud ConsoleでIAM権限を付与

1. `https://console.cloud.google.com/iam-admin/iam?project={プロジェクトID}` を開く（`{プロジェクトID}` は自分のFirebaseプロジェクトIDに置き換え）
2. 手順1でダウンロードしたJSON内の `client_email` の値（例: `firebase-adminsdk-fbsvc@xxxx.iam.gserviceaccount.com`）を一覧から探す。あれば鉛筆アイコンで編集、なければ「+ アクセスを許可」で新規入力
3. 以下の3つのロールを付与して保存
   - **Firebase Rules Admin** (`roles/firebaserules.admin`) — FirestoreルールとStorageルールは同じ「Firebase Rules」APIの管轄なので、これ1つで両方のルール自体のデプロイをカバーします
   - **Service Usage Consumer** (`roles/serviceusage.serviceUsageConsumer`) — 近年のfirebase-toolsではサービスアカウントでのデプロイに必須です
   - **Firebase Storage Admin** (`roles/firebasestorage.admin`) — Storageルールのデプロイ前に、firebase-toolsがプロジェクトのデフォルトバケット名を参照する（`firebasestorage.defaultBucket.get`）ために必要です。これが無いと `Permission 'firebasestorage.defaultBucket.get' denied` というエラーでStorageルールのデプロイだけ失敗します（Firestoreルールは成功します）

### 3. GitHubリポジトリにシークレットを登録

1. リポジトリの **Settings → Secrets and variables → Actions** → 「New repository secret」
2. Name: `FIREBASE_SERVICE_ACCOUNT`
3. Value: 手順1でダウンロードしたJSONファイルの中身をまるごと貼り付け（このJSONはClaudeとのチャットを経由せず、GitHubの画面に直接貼ってください）

プロジェクトIDはこのJSON内の `project_id` からワークフローが自動的に読み取るため、別途シークレットを登録する必要はありません。

登録が完了すると、`.github/workflows/deploy-firebase-rules.yml` により、`firestore.rules`・`storage.rules`・`firebase.json` のいずれかを変更してpushするたびに自動でFirebaseへデプロイされます。`Actions` タブから手動実行（`workflow_dispatch`）することも可能です。
