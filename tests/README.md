# テスト

`index.html` の主要動線を Playwright で確認するスクリプト群です。Firebaseには接続せず、`firebase-mock.js` が差し込む偽のFirebase SDKに対して動きます。**本番のFirebaseプロジェクトには一切アクセスしません。**

## 実行方法

Playwrightが必要です。リポジトリ自体には依存パッケージを持たせていないので、インストール済みの場所を `NODE_PATH` で指定してください。

```bash
# 全部まとめて実行（静的サーバーの起動・停止も込み）
NODE_PATH=/opt/node22/lib/node_modules node tests/run-all.js

# 1本だけ実行したい場合は、先に静的サーバーを立てる
node tests/static-server.js &
NODE_PATH=/opt/node22/lib/node_modules node tests/pin-rate-limit-test.js
```

ポートは環境変数 `PORT` で変更できます（既定は 8175）。

## 合否は自動で判定されます

各テストは `assert.js` のヘルパーで判定し、最後に `report()` を呼びます。`run-all.js` はその出力を集計し、**判定の食い違い・異常終了・自動判定していないテスト**のいずれかがあれば終了コード 1 で終わります。

```
実行: 18本 / 判定: 214件 成功 ・ 0件 失敗
すべて自動判定で合格しました。
```

以前は `項目名 (expect 期待値): 実際の値` を出力して目視で突き合わせていましたが、**判定が食い違っていても異常終了しない**ため、時刻を固定文字列で書いたフィクスチャが壊れているのに3回とも見逃しました（`kinko-stale-record` / `kinko-empty-safe` / `kinko-auto-import`）。目視は安全網になりません。

### 使えるヘルパー

| | |
|---|---|
| `check(名前, 期待値, 実際の値, 補足)` | 完全一致。`Object.is` で比べます |
| `checkIncludes(名前, 実際の値, 含まれるべき文字列)` | 部分一致。画面の文言は前後に余計なものが付くため |
| `checkNotIncludes(名前, 実際の値, 含まれないべき文字列)` | 上の否定 |
| `info(名前, 値)` | **判定しない**参考出力。失敗の原因を追う手掛かり用 |
| `report()` | 最後に必ず呼ぶ。失敗があれば終了コードを 1 にする |

`report()` を呼び忘れたテストは、`run-all.js` が「自動判定していないテスト」として報告します（黙って素通りはしません）。

**`info()` は合否に関係しません。** 本当に確かめたいことを `info()` で出しても誰も気づかないので、確かめたいことは必ず `check` 系で書いてください。

## `stale/` について

**残っているのは `videocall-test.js` の1本だけです。** 2端末を模す専用モック（`firebase-mock-shared.js`）がリポジトリから失われており、修復ではなく書き直しが必要です。

かつてここには14本ありましたが、「機能の変更に追随できていない」という説明は**実態と違っていました**。実際に動かなかった原因は、テストが書かれた後にアプリへ入った環境の変化3つです。

| 原因 | 該当 |
|---|---|
| モックへのパスが `tests/stale/` 移動時に直っていない | 14本（**全本が1行目で落ちていた**） |
| PIN認証の導入（ログインしないとPIN画面が全クリックを遮る） | 13本 |
| オーナー設定が管理者アカウントでのログイン必須になった | 7本 |

つまり**機能に追随できているかどうかを、誰も確認できる状態になかった**ということです。これらを直した結果、12本が `tests/` に戻りました。

本当に廃止されていた機能は次のとおりで、該当箇所だけを外しました。

- **JSONインポート** → テキストインポートに置換（`import-test.js` は削除、`import-text-test.js` が後継）
- **件数の入力欄** → ボタングリッドに置換
- **画面内の忘れ物リマインドカードとそのタップ絞り込み** → 自動投稿のリマインドに置換（`reminders-test.js` が後継）
- **未解決項目の持ち越し質問** → 廃止（現行の `handover-prev-answer-test.js` が「出ないこと」を検証している）

**テストを `stale/` に移すときは、モックへのパスを直してください。** 直さないと、そのテストは以後1行目で落ち続け、「動かない理由」を誰も確かめられなくなります。

## テストを書くときの注意

- **確かめたいことは `check` 系で書いてください。** `info()` は出力するだけで判定しません
- **型もそのまま比べます。** `innerText()` は文字列を返すので、件数を確かめるときは `Number(...)` を通してください（`1` と `"1"` は出力すると見分けが付かないため、目視では永久に気づけません）
- **数と配列を比べないでください。** 件数を確かめたいときは `.length` を渡します（変換時に `check('...', 3, await readNotebookTexts())` と書いてしまい、配列と数を比べて必ず失敗する状態を作りました）
- **`.settings-btn` は⚙️と🌐の両方に一致します。** 必ず `:has-text("⚙️")` で絞り、`.home-topbar` か `.active-view` でスコープしてください。`stale/` の大半はこれが原因で動かなくなりました
- 店舗が2つ以上登録されていると、起動時に店舗選択モーダルが開いてクリックを遮ります。先に `.store-option-btn` で店舗を選んでください
- `<details>` が閉じていると `innerText` が空になります。先に `summary` をクリックするか、`evaluate(el => el.textContent)` を使ってください
- モックの `onSnapshot` は同期的に発火します。購読を解除する変数を、同じ式の中で参照しないでください
- **日時を固定文字列で書かないでください。** 引継ぎの `createdAt` も金庫記録の `datetime` も、`Date.now()` からの相対で作ってください。固定時刻にすると、実行した時間帯やタイムゾーン次第で「最新の引継ぎ」が入れ替わったり、点検記録が未来扱いになったりして、判定がすり抜けます（実際に2回踏みました）
